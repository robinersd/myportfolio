# Portfolio tech stack and design sources

Audited against the running `robinersd` source on October 12, 2026. This is an inventory of the current implementation, rather than a list of every technology shown in the portfolio.

## 1. The portfolio itself

| Area                  | What is actually used                                                                                         | Source / documentation                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Page structure        | HTML5; semantic navigation, forms and native dialogs                                                          | [HTML standard](https://html.spec.whatwg.org/)                                                                                    |
| Styles                | Custom CSS: variables, flex/grid layout, responsive media queries, transforms, keyframes and glass surfaces   | [CSS specifications](https://www.w3.org/Style/CSS/)                                                                               |
| Frontend behavior     | Plain JavaScript ES modules; DOM events, Fetch, History and browser storage                                   | [JavaScript specification](https://tc39.es/ecma262/)                                                                              |
| Local server          | Node.js built-in HTTP, filesystem, path and OS modules                                                        | [Node.js documentation](https://nodejs.org/docs/latest-v24.x/api/)                                                                |
| Hosting configuration | Vercel static output, route rewrites and a serverless chat endpoint                                           | [Vercel configuration](https://vercel.com/docs/project-configuration/vercel-json)                                                 |
| Chat provider         | Server-side fetch to `https://api.xkiro.com/v1/chat/completions`; `XKIRO_MODEL` is configurable               | Endpoint recorded in `api/chat.js`; default model is `qwen/qwen3-omni-flash:free`                                                 |
| Spotify playback      | Official Spotify embeds and iframe API; default playlist prepared on page load with no autoplay               | [Spotify iframe API](https://developer.spotify.com/documentation/embeds/references/iframe-api)                                    |
| Photo preparation     | Canvas resizing/compression and FileReader; JPG, PNG and WebP input                                           | Native browser APIs in `chat-media.js`                                                                                            |
| Voice recording       | Web Audio + AudioWorklet PCM capture; ScriptProcessor compatibility fallback; MediaRecorder as final fallback | [Web Audio specification](https://www.w3.org/TR/webaudio/), [MediaStream Recording](https://www.w3.org/TR/mediastream-recording/) |
| Voice format          | Custom 16 kHz, mono, 16-bit PCM WAV encoder; maximum 30 seconds                                               | `chat-media.js`, `pcm-recorder.js`, `pcm-worklet.js`                                                                              |
| Speech text           | Browser SpeechRecognition when available; visitor can edit the transcript                                     | Browser-provided feature, not an installed speech SDK                                                                             |
| Formatting            | Prettier 3.9.9 used for this cleanup; `.prettierrc.json` stores formatting settings                           | [Prettier](https://prettier.io/docs/)                                                                                             |

Both package manifests have no runtime npm dependencies. Running the portfolio needs Node.js 22.9 or newer; Node.js 24 LTS is recommended in the setup guide. React, Tailwind, Vite, GSAP, Framer Motion, Bootstrap, shadcn/ui and animation npm packages are not imported by this portfolio. The current React Bits and StaggeredGrid references are adapted to native JavaScript/CSS/canvas.

The portfolio has no database. Public content lives in `data.js`. Theme preference uses browser localStorage; chat state and recorded attachments are kept in the current page session. Uploaded images go to the configured chat service for analysis. The backend sends reviewed speech text for voice analysis because the current gateway does not handle raw `input_audio` reliably; it does not analyze tone or other sounds from the recording.

## 6. Licenses and editing locations

Keep `assets/REACT-BITS-LICENSE.md`, `icons/DEVICON-LICENSE.txt` and source notices when distributing the code. Third-party brand marks retain their owners' rights. The private `originals/` folder stores retained source photos, the resume and edited source images; the local server only serves `site/`, and the private folder is ignored for repository sharing.

Edit content in `data.js`, page markup in `portfolio.js`, appearance in `styles.css`, and behavior in the matching module listed above. `.prettierrc.json` uses two spaces, single JavaScript quotes, a 100-character target width and LF newlines. Long URLs, SVG path geometry and literal prompt text may exceed that width without changing their contents.

## Resume activation and current media improvements

The live-site resume gate uses native JavaScript and browser sessionStorage. Public static resume images remain accessible directly as requested; this is an interaction gate rather than authentication. No resume secret, database or authentication package is required. Project images are resized/compressed into responsive WebP variants using Pillow during source preparation (not a runtime dependency). Certificate viewing uses a native HTML dialog with custom responsive CSS. Local static responses support ETag revalidation and one-hour image caching.

## User-supplied gallery and project components

PixelatedImageTrail comes from the user’s pasted source; the original website was not specified. It is adapted to native JavaScript/CSS in pixel-gallery.js and gallery-trail.css. TeamRevealGrid has been removed and the custom stacked project deck restored. Gallery thumbnails are removed; trail tap and keyboard selection open the compact viewer. The Medicare image edit remains active. The certificate uses a built-in imagegen restoration for clarity, with the original in originals/certificates/oop-original.jpg and the selected output in originals/edited-images/oop-certificate-restored.png. Preview and dialog CSS preserve the landscape aspect ratio. Redundant root update reports and edit logs were removed after consolidating the current file guide here and in README.md.

Navigation refinement: the requested Explore projects, View resume, View all, View gallery, GitHub and LinkedIn links display text without decorative diagonal arrows. Gallery chevrons remain functional previous/next controls. Both photo viewers use native dialogs, Escape/backdrop closing and scroll locking; no new runtime library was added.

Skills/tool image previews now hide the panel, visible heading and caption. They retain the existing compact image bounds, accessible labels, close/Escape/backdrop behavior and logo fallback when a preview fails to load.

Header layout: the RBD text brand is removed; the theme switch sits on the left and Projects/Highlights/Gallery/Contact sit on the right. The header and profile share the same responsive container, with compact phone spacing and no added library.

Theme-toggle motion: the sliding thumb has its own named view-transition group, so its 240ms position animation remains visible during the circular page reveal. The ordinary CSS slide remains the fallback; reduced-motion preferences are retained. See [MDN view transitions](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using).

Chat flow: three custom intro replies, then one farewell after the visitor’s next text response. Resume activation-help questions and the exact activation command take priority. Normal AI answers and photo/voice analysis continue afterward. The frontend and backend share a resume-help intent check, and the backend strips unrequested activation-command hints from provider replies.
